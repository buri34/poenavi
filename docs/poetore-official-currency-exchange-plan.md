# ぽえとれ GGG公式Currency Exchange価格対応計画

更新日: 2026-09-27
状態: Phase 3-1実装済み・最新実取引追随をMac検証済み
対象: PoE 1／PoE 2のCurrency Exchange対象品

## 目的

ぽえとれがpoe.ninjaから取得している参考価格のうち、GGG公式Currency Exchangeの
実約定データで代替できる品目を、公式価格へ段階的に移行する。

誤った内部ID、出来高0の板、単発の極端な約定、古いローカルキャッシュを現在価格として
表示しない。公式価格を確定できない間は、既存のpoe.ninja価格を暫定表示する。

## 対象と対象外

### 対象

- Currency Exchange APIに含まれるスタック品
- 検索アイテムの参考価格
- 関連アイテム／素材の参考価格
- Divine OrbとChaos Orb／Exalted Orbの換算
- PoE 2エクスペディション報酬価格
- PoE 2のルーン等の仮挿入費用・回収価値計算

### 対象外

- Unique、装備品、Map、個別variantなどCurrency Exchange対象外品
- 公式Trade APIの出品一覧と最安出品価格
- poe.ninjaの7日推移グラフ

対象外は既存のpoe.ninja／公式Trade API経路を維持する。

## 確定した基本方針

### 1. ゲーム別の基準通貨

- PoE 1: Chaos Orbを基準通貨、Divine Orbを高額品の別建て通貨とする。
- PoE 2: Exalted Orbを基準通貨、Divine Orbを高額品の別建て通貨とする。

基準通貨建てとDivine建てを最初から混合しない。各経路を独立して時間集計し、表示時に
採用した経路を記録する。

価格の採用経路と、画面上の表示通貨は分離する。基準通貨建てを採用した場合でも、価格が
同じ価格表の検証済みDivine／基準通貨レートで1 Divine以上に相当するなら、可読性のため
Divineへ換算して表示する。内部計算と監査用には、換算前の基準通貨価格も保持する。

### 2. 取得単位

公式APIは1アイテムずつ呼ばず、完了済み1時間の全市場を一括取得する。

- 起動中は、完了した新しい1時間をバックグラウンドで1回取得する。
- 起動時は、選択中のrealmについて直近24時間の未取得時間だけを時刻指定で補完する。
- API取得、展開、集計はUIスレッドで実行しない。
- 検索時はネットワークへ行かず、完成済みのローカル価格表を辞書参照する。

製品はOpenClaw Cronや開発Macの収集器へ依存しない。現在の独立収集器は検証用として残す。

### 3. 履歴範囲

製品が保持する公式生データは直近24時間だけとする。7日履歴と7日バックフィルは実装しない。

次の3状態を区別する。

- 取得済み・出来高あり
- 取得済み・出来高0
- アプリ停止や取得失敗による未取得

未取得を出来高0として扱わない。直近24時間に未取得時間がある間は公式価格表を確定せず、
poe.ninjaを暫定表示する。

### 4. キャッシュ鮮度

- 最新完了時間まで取得済み、または遅れが最大1～2時間のキャッシュだけを即時利用候補にする。
- それより古いキャッシュは現在価格として表示しない。
- 古い場合はpoe.ninjaを暫定表示し、直近24時間をバックグラウンドで再構築する。
- 公式APIとpoe.ninjaの両方を取得できない場合、古い値を黙って表示せず価格取得不可とする。

1～2時間は保存済みデータと実運用で確定する暫定境界であり、実装時に定数化する。

## 公式価格の計算

### 1. 1時間の観測値

市場ペアの両側で`volume_traded > 0`のときだけ実約定ありとする。

```text
1個あたり価格 = 建て通貨の交換量 / アイテムの交換量
```

出来高1も有効な実約定として採用候補にする。固定の最低総出来高は設けない。出来高0、
片側出来高0、市場ペア欠落は価格根拠にしない。

### 2. 最新実取引の採用と単発極端値の確認

- 直近24時間内で実取引が成立した最新1時間の平均価格を表示候補にする。
- 最新時間を除く過去23時間に3観測以上ある場合、その中央値を異常検知の基準にする。
- 最新値と過去中央値の差が3倍以内なら、最新値をそのまま採用する。
- 3倍を超える場合も、次のいずれかを満たせば最新値を採用する。
  - 直前の完了時間にも取引があり、価格差が1.5倍以内。
  - 同時間の売買両側に在庫があり、注文価格帯の開きが3倍以内で、最新値が価格帯の上下20%以内。
  - 同一基準通貨へ正規化したpoe.ninja価格との差が2倍以内。
- どの裏付けもない単発極端値だけを保留し、poe.ninja参考価格へフォールバックする。
- 次の完了時間に同水準の実取引が続けば、直前価格による裏付けが成立して公式価格へ切り替える。

24時間履歴とpoe.ninjaは表示価格を平均化するためではなく、最新実取引の異常検知にだけ使う。

### 3. 直近24時間に1～2観測しかない場合

最新の実取引価格を候補にする。poe.ninjaとの差が2倍以内、直前時間との差が1.5倍以内、または
注文価格帯との整合があれば採用する。比較材料がなくpoe.ninjaも取得できない場合は、実取引価格を
採用しつつ内部状態へ観測少を記録する。poe.ninjaと2倍を超えて矛盾し、他の裏付けもなければ
poe.ninja参考価格へフォールバックする。

### 4. 直近24時間に実約定がない場合

公式価格なしとし、poe.ninjaを暫定表示する。24時間より古い公式約定を現在価格として表示しない。

## 基準通貨建てとDivine建て

各経路へ同じ最新実取引優先、単発極端値確認、観測少のpoe.ninja比較を適用する。

- 基準通貨建てに有効な実約定がある: その価格を採用し、下記の表示通貨ルールを適用する。
- 基準通貨建てがなく、Divine建てに有効な実約定がある: Divine価格をそのまま主表示する。
- 必要な計算では、検証済みのDivine／基準通貨レートを使って基準通貨相当額も保持する。
- どちらにも実約定がない: poe.ninjaを暫定表示する。

Divine建てを一律に不採用にしない。実際にDivineで成立した価格は、単発異常判定を通れば
表示候補にする。画面とログでは、直接基準通貨、Divine直接、poe.ninja暫定のどれを採用したか
判別できるようにする。

## 表示通貨の選択

内部の共通価格単位は、PoE 1ではChaos、PoE 2ではExaltedとする。画面上の主表示だけを
次の規則で選ぶ。

1. Divine直接経路を採用した価格は、1 Divine未満でも実際の約定通貨であるDivineで表示する。
2. 基準通貨直接経路を採用し、`基準通貨価格 >= 1 Divineの基準通貨レート`なら、
   `基準通貨価格 / Divineレート`をDivineで表示する。
3. 基準通貨直接経路を採用し、1 Divine未満ならChaos／Exaltedで表示する。
4. 境界は1 Divineちょうどを含む。0.94 Divineなどの先行切替は行わない。
5. 有効なDivineレートがない場合は無理に換算せず、採用した経路の通貨で表示する。

例えばPoE 2で1 Divine = 1,000 Exalted、採用したExalted直接価格が10,000 Exaltedなら、
主表示は`10 div`とする。ただし出典はDivine直接約定ではなく`ggg_direct_base`のまま保持し、
ログには換算前の`10,000 Exalted`、使用レート、レートの観測時間も記録する。

Divine換算表示は見やすさのための整形であり、価格候補の採否や異常判定を変更しない。
同じ換算規則を、検索アイテム、関連素材、エクスペディション報酬、仮挿入費用・回収価値へ
共通適用し、画面ごとに通貨表示が食い違わないようにする。

## 内部IDの安全性

- `Metadata/Items/...`をRePoE由来の検証済み辞書へ厳密一致させる。
- NFKC、casefold、空白正規化後も、名前からIDへの対応が一意な場合だけ採用する。
- 部分一致、曖昧一致、画像名推測を使わない。
- 未対応ID、同名複数ID、競合名は隔離し、poe.ninjaへフォールバックする。
- Chaos Orb、Divine Orb、Exalted Orbをgolden IDとして固定し、交換した負例が失敗することを確認する。

## 起動から価格表示まで

1. 選択中のPoE版、リーグ、最新完了時間を確定する。
2. 直近24時間の取得状態を確認する。
3. 鮮度条件を満たす完全な24時間キャッシュがあれば、公式価格表を即時利用する。
4. 欠落または古いキャッシュなら、poe.ninjaを暫定表示する。
5. バックグラウンドで直近24時間の欠落だけを取得する。
6. 24時間が揃ったら価格表を1回構築し、そのセッション中に公式価格へ切り替える。
7. 以後は完了した新しい1時間だけを追加し、24時間より古い時間を削除して差分更新する。

同じ時間を重複取得・重複集計しない。リーグ切替中の古い結果を別リーグへ表示しない。

## 表示と出典

価格結果には少なくとも次を保持する。

- 表示額と表示通貨
- 換算前の採用額と採用通貨
- 基準通貨相当額
- Divine換算表示に使用したレートとレート観測時間
- 出典: `ggg_direct_base`／`ggg_direct_divine`／`poe_ninja_fallback`
- 対象リーグとrealm
- 最新観測時間
- 24時間内の有効観測数
- 観測少、poe.ninjaとの大差、除外時間などの内部判定理由

UIの文言は、`カレンシー交換 直近価格`と`poe.ninja 参考価格`を区別する。公式価格の
ツールチップには、直近24時間以内に取引が成立した最新1時間の平均価格であることを示す。既存の7日推移、
poe.ninjaリンク、Currency Exchange対象外品は既存表示を維持する。

## 実装段階

### Phase 1: 製品外アルゴリズム更新

- 独立検証ツールを24時間ローリング方式へ更新する。
- 直近24時間、出来高1以上、中央値、単発異常除外を実装する。
- 1～2観測時のpoe.ninja比較を追加する。
- 基準通貨建てとDivine建ての主表示候補を別々に出力する。
- 保存済み196時間へ各24時間窓で再適用する。

完了条件:

- PoE 1／PoE 2それぞれで採用、poe.ninja暫定、取引なし、単発異常の件数を報告できる。
- ディアーラの服従のChaos価格7cを維持し、単発の極端なDivine価格を除外できる。
- 複数時間続く新価格を単発異常として除外しない。

実施結果（2026-09-27）:

- 196時間、各173個の24時間窓へ再適用済み。
- 最新24時間はPoE 1で895品中868品を基準通貨直接、22品をDivine直接から採用した。
- 最新24時間はPoE 2で598品中479品を基準通貨直接、114品をDivine直接から採用し、
  3品をpoe.ninja暫定、2品を価格なしとした。
- ディアーラの服従の388.5 Divine単発値を主価格にせず、該当窓のChaos直接価格7cを採用した。
- 内部ID交換、欠落ID、正規化同名衝突の負例を検出し、17単体テスト、Ruff、構文検査に成功した。
- 過去時点のpoe.ninja価格は保存していないため、poe.ninja比較は最新窓だけ完全検証した。
  過去窓の単一観測は`single_observation_unchecked`として不確実性を明示した。

Phase 1判定は`PASS_WITH_LIMITATION`とし、Phase 2の製品内shadow modeへ進行可能とする。

### Phase 2: 製品内shadow mode

- ぽえとれ内部で公式24時間価格表を構築する。
- 表示は既存のpoe.ninja価格のまま、公式候補、採用経路、判定理由、処理時間をログへ記録する。
- 起動直後、古いキャッシュ、24時間欠落、リーグ切替、取得失敗、復旧を検証する。
- UIスレッドの停止がなく、検索時の辞書参照が既存より遅くならないことを確認する。

実施結果（2026-09-27）:

- `src/poetore/official_exchange.py`へPoE 1／PoE 2共通エンジンとrealm別プロファイルを実装した。
- 製品キャッシュは`poetore-official-exchange/raw/<realm>/<league>/`へ保存し、各リーグ24時間、
  1時間1ファイルを上限として毎時差分更新する。破損時間は次回同期で削除・再取得する。
- バンドル済みRePoE由来ID辞書を厳密一致にだけ使用し、未対応ID、正規化同名衝突、golden通貨ID
  不一致を表示候補から隔離する。
- リーグ確定・リーグ変更・検索・1時間タイマーを同期契機とし、実際の取得と再構築はdaemon threadで
  実行する。検索時の公式照合は完成済みメモリ表だけを参照し、公式APIへアクセスしない。
- 画面は従来のpoe.ninja表示を維持し、公式候補、採用経路、観測数、除外数、poe.ninja比較、
  Divine換算、処理時間を`poetore-official-exchange/shadow.jsonl`へ記録する。ログは5 MiB×3世代で
  ローテーションする。
- 実データの初回24時間取得はPoE 1が約3.7秒、PoE 2が約5.4秒、再起動相当のキャッシュ再構築は
  両方合わせて約0.27秒だった。保存量は両realm合計約2.0 MBで、未対応ID・同名衝突は0件だった。
- 初回、毎時差分、1週間停止、stale cache、破損復旧、リーグ分離、Divine直接、UI非変更、
  検索時ネットワークなしを自動テストへ固定した。Mac側の対象・全体回帰は成功した。

Phase 2の判定は`PASS`とする。Windows配布版では初回確認でPyInstaller onedirの辞書参照先が
1階層ずれる不具合を検出したが、`_internal/data/...`を解決する修正後、PoE 1は899品、
PoE 2は658品で同期に成功した。両方とも未対応ID・同名衝突・修正版起動後の同期失敗は0件で、
検索時の公式候補採用、`None`候補除去、直後の重複ログ抑止まで実機確認した。

### Phase 3: 公式価格表示の段階解放

- shadow modeの検証を通ったCurrency Exchange対象品だけ公式価格へ切り替える。
- 公式価格が未確定、取得失敗、ID未対応の場合はpoe.ninjaを暫定表示する。
- 価格の出典を画面上で区別する。
- 対象外品、7日推移、出品検索は既存経路を維持する。

#### Phase 3-1: 検索アイテムの参考価格欄

- Currency Exchange対象品で`accepted_direct`または`accepted_divine`となった時だけ、主表示を
  `カレンシー交換 直近価格`へ切り替える。
- 公式同期中、価格未確定、ID未対応、取得失敗時は`poe.ninja 参考価格`を表示する。
- Currency Exchange対象外品は従来の`poe.ninja 参考価格`を維持する。
- 公式価格を主表示する場合も、取得済みのpoe.ninja 7日推移とリンクは比較情報として残す。
  poe.ninja自体が取得不能でも公式候補が確定していれば公式価格だけを表示できる。
- 初回24時間同期が検索後に完了した場合は、選択中のPoE版・リーグ・アイテムが一致する時だけ
  現在の検索アイテムを自動再評価し、同じセッション内で暫定価格から公式価格へ切り替える。
- PoE 1のChaos、PoE 2のExalted、Divine直接、1 Divine以上のDivine換算には、Phase 2で
  検証済みの共通価格エンジンの`display_amount`と`display_currency`をそのまま使用する。

実施結果（2026-09-27）:

- PoE 1／PoE 2の検索参考価格へ公式候補を接続し、公式価格とpoe.ninja参考価格を表示上で区別した。
  公式未確定のフォールバックとCurrency Exchange対象外は内部状態とツールチップで判別する。
- 同期完了通知から現在アイテムを自動再評価し、同じセッション内の表示切替を実装した。
- 公式価格単独表示、poe.ninja比較情報の併記、stale非同期結果の破棄をテストへ固定した。
- PoETore関連1,579件・15サブテスト、全145テストファイルの分離回帰、重大静的検査、
  compileall、差分検査に成功した。Windows配布版の最終表示確認は固定ミラーで行う。

## テスト計画

### 単体テスト

- 市場ペアの向きに関係なく1個あたり価格を正しく計算する。
- 両側出来高1を有効、片側0を無効にする。
- 最新実取引、過去中央値から3倍以内、3倍超の単発極端値を区別する。
- 3倍超または1～2観測で、直前時間、注文板、poe.ninjaによる裏付けとフォールバックを分岐する。
- 基準通貨市場なし／Divine市場ありでDivine価格を主表示候補にする。
- 基準通貨直接価格が1 Divine未満、1 Divineちょうど、1 Divine超の場合に、表示通貨を
  基準通貨、Divine、Divineへ正しく切り替える。
- 1 Divine未満のDivine直接約定は、基準通貨へ戻さずDivineで表示する。
- 基準通貨からDivineへ換算表示しても、出典を`ggg_direct_divine`へ変更しない。
- Divineレートが無効または欠落している場合は、基準通貨表示を維持する。
- 未取得時間と出来高0時間を区別する。
- 24時間窓から古い時間を削除し、同じ時間を重複集計しない。
- stale cacheを現在価格として返さない。

### 負例テスト

- Chaos Orb／Divine Orb／Exalted OrbのID交換
- 未対応ID、同名衝突、競合名
- 1時間だけの100倍以上の極端値
- poe.ninjaと大差がある単一観測
- Divine換算に使う通貨レートの片側出来高0
- 表示額の換算レートと価格表のリーグ／realm／観測時間が一致しないケース
- リーグ切替後に前リーグの非同期結果が戻るケース
- 取得途中でアプリを終了し、次回起動で欠落を再取得するケース

### 統合・性能テスト

- 初回起動、1日停止、1週間停止からの復旧
- 24時間バックフィル中も検索・OCR・Trade検索が操作可能
- 完成価格表の検索がネットワークアクセスなしで完了
- 毎時差分更新でUI停止が発生しない

- Windows配布環境でキャッシュ作成、原子的更新、破損復旧が機能する

- 出来高0の板を価格根拠にしない。
