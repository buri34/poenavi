# ぽえとれ 任意レート表示 実装計画

更新日: 2026-09-27
状態: 工程1〜3完了・工程4以降未実装
仕様正本: `docs/poetore-custom-rate-display-spec.md`

## 実装原則

- 各工程を単独でテスト・レビュー・コミットできる粒度にする。
- UIは、直接ペア価格・候補カタログ・永続設定・アイコンキャッシュの各境界が安定してから接続する。
- 既存の検索画面上部の換算ボタンと、検索価格の公式優先経路は変更しない。
- 既存の公式24時間スナップショットを再利用し、任意レート表示専用のAPI取得は増やさない。
- PoE 1／PoE 2、リーグ、ペアの向きをすべて明示的なキーとして扱う。

## 依存関係

```text
工程1 カタログ
   ├─→ 工程4 アイコン
   └─→ 工程5 管理画面

工程2 登録モデル・保存 ─→ 工程5 管理画面 ─┐
                                           ├─→ 工程6 メイン画面
工程3 直接ペア価格・同期状態 ───────────────┘

工程4 アイコン ───────────────────────────→ 工程6 メイン画面

工程1〜6 ─→ 工程7 統合・全体検証 ─→ 工程8 Windows実機確認
```

- 既存の英語名辞書と、検証済み日本語ソース・公式Trade staticデータからカタログを再生成できるスクリプトを用意する。
- 日本語名が未確認の品は生成結果から除外する。
- PoE 1の例外分類とPoE 2の例外分類を生成テストへ固定する。
- `16px-Divination_card_inventory_icon.png`を配布アセットへ取り込み、PoE 1占いカードを共通アイコン種別にする。

### 主な変更候補

### テスト・完了条件

- 日本語名なしの候補が混入しない。

- 共通カード画像が16×16 PNGとして配布対象に含まれる。

- PoE 1は1,162件、PoE 2は752件の日本語カタログを生成した。
- 現行24時間データの未収録は、日本語未確認の既知9件（PoE 1が1件、PoE 2が8件）だけである。
- PoE 1占いカード469件は共通16×16 PNGを使い、個別画像URLを保持しない。
- 公式ソースURLとレスポンスSHA-256を生成物へ記録した。

## 工程2: 登録ペアのドメインモデルと保存を実装する

- `src/utils/config_manager.py`
- `config/default_config.json`

### テスト・完了条件

- デフォルト削除後の空配列が再起動後も維持される。
- リーグを変更しても同じPoE版の登録順が変わらない。
- 無効ID・壊れた型・重複・6件超を読み込んでも安全な値へ正規化される。
- 追加・削除・上下移動のたびに保存コールが1回だけ発生する。

### コミット単位

`feat: persist custom exchange rate pairs`

## 工程3: 任意の直接ペア価格と同期状態を公開する

**状態: 完了（2026-09-27）**

### 実装

- 既存24時間スナップショットから、任意の`left_item_id → right_item_id`だけを抽出する公開APIを追加する。
- 価格方向を常に「左1個あたりの右数量」に正規化する。
- `_pair_sample`と既存の異常値判定を再利用し、クロス換算は行わない。
- 結果を少なくとも次の状態へ分ける。
  - `available`: 有効な直接約定価格あり
  - `no_trades`: 24時間に直接約定なし
  - `unconfirmed`: 直接約定はあるが異常値判定で保留
  - `unavailable`: 同期未完了・キャッシュなし・期限切れ
- 候補一覧用に、現在の24時間テーブルへ登場した内部ID集合を公開する。
- 現在のテーブルの`end_hour`、最新完了時間との差、同期中か否かを公開する。
- 起動時と10分ごとの確認は`queue_sync`を使い、新しい完了時間がない場合はネットワーク取得しない。
- 手動確認結果を「更新あり／新データなし／失敗」で返せるようにする。
- 表示用の前回確定値を、PoE版＋リーグ＋ペア方向単位で24時間以内だけ復元できる永続キャッシュへ保存する。

### 主な変更候補

- `src/poetore/official_exchange.py`
- 新規の任意レート結果／表示キャッシュモデル
- `tests/test_official_exchange.py`

### テスト・完了条件

- A→BとB→Aが逆数関係になり、数量方向を取り違えない。
- 直接市場がない時に、Divine等を介した価格を返さない。
- 注文板だけの市場を`available`にしない。
- 異常値保留を`no_trades`と区別する。
- 同じ`end_hour`の再確認ではAPI取得0件となる。
- 新時間だけ1時間分を取得し、失敗後は次回確認で再試行できる。
- 24時間以内の前回値だけ復元し、24時間超は表示しない。
- PoE版・リーグ・ペア方向のキャッシュ混入がない。

### コミット単位

`feat: resolve direct custom exchange pairs`

### 実装結果

- 24時間スナップショット内の全市場を、左右それぞれの方向へ正規化した直接ペア系列として価格表へ保持する。
- `direct_pair`は`available`、`no_trades`、`unconfirmed`、`unavailable`を返し、別市場を介したクロス換算を行わない。
- `exchange_item_ids`で24時間内に登場したID集合、`sync_state`で完了時間・遅延時間・同期中・利用可否を公開する。
- `queue_sync`へ`on_checked`を追加し、`updated`、`no_new_data`、`failed`を通信結果として通知する。同じ完了時間は取得処理を開始しない。
- PoE版・リーグ・左右方向を完全キーとする前回確定値キャッシュを追加し、24時間以内の値だけ復元する。
- 直接／逆方向、取引なし、注文板だけ、異常値保留、差分1時間取得、失敗後再試行、期限、ゲーム版・リーグ・方向分離を固定テストした。

## 工程4: 永続アイコンキャッシュを実装する

### 実装

- `%APPDATA%\\PoENavi\\poetore-icon-cache`を使うアイコン取得サービスを追加する。
- URL文字列を含む安定キーで保存し、URL変更時だけ別画像として取得する。
- メモリキャッシュ、ディスクキャッシュ、ネットワーク取得、プレースホルダーの順に解決する。
- 同じURLへの同時要求を1本へまとめる。
- 画像形式・サイズ上限・HTTP成功を検証してから原子的に保存する。
- 失敗結果は永続的な成功扱いにせず、次回表示時に再試行可能にする。
- 占いカード共通画像はネットワークを使わず配布アセットを返す。

### テスト・完了条件

- 初回表示だけ取得し、再起動相当ではディスクキャッシュを使って通信しない。
- 同じURLの並行要求でネットワーク取得が1回だけになる。
- URL変更時は新しい画像を取得する。
- 壊れた画像、巨大レスポンス、通信失敗でプレースホルダーとなる。
- UIスレッドで同期ネットワークI/Oを行わない。

### コミット単位

`feat: cache poetore exchange icons`

## 実装着手順

着手順は`工程1 → 工程2 → 工程3 → 工程4 → 工程5 → 工程6 → 工程7 → 工程8`とする。
工程1と工程2はコード上の依存が薄いが、候補IDを設定へ保存するため、カタログのID契約を先に固定する。

## 主要リスクと先回りするテスト

- **価格方向の逆転**: A→B／B→Aの同一市場フィクスチャで逆数を固定する。
- **空状態へデフォルトが復活**: 「キーなし」と「空配列」を別ケースで固定する。
- **同期失敗を取引なしと誤表示**: 通信状態と価格判定状態を別モデルにする。
- **候補一覧と登録済み一覧の消失**: 候補の24時間集合と永続登録を別データとして扱う。
- **UIスレッド停止**: 価格同期・画像取得とも、遅いフェイク通信で画面操作可能性を検証する。
- **PoE版／リーグ混入**: 全キャッシュキーを境界テストへ固定する。
- **配布版だけデータ欠落**: source／PyInstaller相当の両パスでカタログと共通画像を解決する。
