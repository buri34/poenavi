# ぽえとれ 高精度OCRアーキテクチャ

この文書は、アビス冒涜Modチェックで使うNDLOCR-Lite連携の現行仕様を説明する。
実装途中の計画、移行日誌、個別ビルド記録は含めない。

## 目的と適用範囲

Windows OCRで冒涜Mod本文は読めたが、Tier判定に必要な数字だけ欠落した場合に限り、
NDLOCR-Liteで数字を再確認する。Windows OCRを主経路とし、高精度OCRを一般的な全文OCRや
エクスペディション報酬チェックへ流用しない。

## 配布方式

高精度OCRはPoENavi本体ZIPへ同梱しない。専用の公開済みPre-release
`ndlocr-pack-v1.3.1-r1`から、次の2 assetを取得する。

- `PoENavi-HighAccuracyOCR.zip`
- `PoENavi-HighAccuracyOCR.zip.sha256`

管理画面を開いた時、未導入または非互換の場合だけバックグラウンド取得を開始する。
PoENaviの通常起動や他のOCR機能では取得しない。

導入先は既定で次のとおり。

```text
%LOCALAPPDATA%\PoENavi\ocr-packs\ndlocr-1.3.1\
```

テストでは`POENAVI_NDLOCR_PACK_DIR`と`POENAVI_NDLOCR_PACK_BASE_URL`で隔離先と取得元を
上書きできる。

## パックの検証

`ndlocr_pack.py`は次の条件を満たすパックだけを導入する。

1. `.sha256`とダウンロードしたZIPのSHA-256が一致する
2. ZIP内に絶対パス、親ディレクトリ遡及、リンク等の危険なentryがない
3. 自己完結ヘルパー、ONNXモデル4本、ライセンス2本が揃っている
4. 一時ディレクトリで検証後、完成したディレクトリへ置換する
5. markerのパック版、Releaseタグ、asset SHAが期待値と一致する

途中失敗、キャンセル、ハッシュ不一致では既存の正常パックを壊さず、一時ファイルを破棄する。

## 実行時ライフサイクル

`ndlocr_lite.py`はJSON Linesで通信するCPU-only sidecarを必要時だけ起動する。

- 数字救済が不要なら起動しない
- 1回目の起動後は同じプロセスとモデルを再利用する
- 最後の利用から180秒で終了する
- sidecar起動中にアビス冒涜チェックのホットキーを受け付けた場合、期限を180秒へ更新する
- sidecar停止中のホットキーは起動理由にしない
- 他機能のWindows OCR利用では期限を更新しない
- 画面読取OFF、モード切替、更新開始、PoENavi終了時は即時停止する

待機中はポーリングせず、入力待ちとタイマーでCPU消費を抑える。

## ユーザー表示

高精度OCRパックの取得状態は、アビス冒涜Modチェックの管理画面内だけに表示する。

- 未導入: 準備開始の案内
- 取得中: 進捗率とプログレスバー
- 検証・展開中: インストール中の案内
- 完了: 利用可能なパック版
- 失敗: Windows OCRは継続利用できる説明と再試行ボタン

実際にNDLOCRを使う時はゲーム画面右上へ案内を出す。

- 初回起動: 理由、高精度OCR準備中、初回のみ時間がかかる旨を即時表示
- 常駐再利用: 同じリクエストが400msを超えた場合だけ再確認中の案内を表示
- 完了、失敗、キャンセル時: 案内を直ちに消す

## 性能上の根拠

Windows実測では、モデル初回起動は約11.9秒、常駐後の推論は平均約0.75秒だった。
一方、常駐中は物理RAM約0.8GiBを維持したため、常時起動ではなく180秒のidle終了を採用した。
この数値は採用判断の目安であり、機種ごとの保証値ではない。

## ライセンス

NDLOCR-Lite 1.3.1と依存ライブラリのライセンスはOCRパックへ同梱する。PoENavi側の帰属、
変更内容、非提携表示は`THIRD_PARTY_NOTICES.md`に記載する。ライセンスファイルが欠けたパックは
ビルド時・導入時の両方で拒否する。

## 回帰テスト

変更時は最低限、次を確認する。

1. パックURL、固定SHA、marker互換性
2. ZIP安全検査と原子的導入
3. 未導入・導入済み・取得失敗の管理画面状態
4. Windows OCR優先と数字欠落時だけのNDLOCR救済
5. 初回起動、再利用、180秒終了、ホットキー延長
6. 終了・更新・モード切替時の子プロセス停止
7. 400ms遅延表示と表示解除
8. ライセンス、モデル、ヘルパーのパック構成
