# PoE2版ぽえとれ 実機テスト

このフォルダを、Windows実機テストの作業入口とする。

## 作業ファイル

- `windows-test-run.csv`: Windows実機で記入する短縮作業票（まずやる10本＋追加確認8本）
- `windows-test-cases.csv`: 64ケースの詳細仕様・追跡用台帳。原則として実機では編集しない
- `search-matrix-audit.csv`: 装備27カテゴリのレアリティ／プリセット／検索範囲の構造監査結果
- `search-matrix-audit.json`: 上記監査の機械可読サマリーと全行
- `search-real-copy-audit.csv`: 日英実コピーfixtureの解析・最終Trade2 identity監査結果
- `../../tests/fixtures/poe2/real_copy_bilingual.csv`: 収集済み日英実コピーの自動テスト用fixture台帳
- `../poetore-pending-tasks.md`: ぽえとれ全体の残タスク正本
- `../poetore-poe2-development.md`: PoE2版の実装・検証履歴

実機で編集するのは`windows-test-run.csv`だけとする。詳細仕様、自動テスト用fixture、原因分析は
Mac正本で管理する。詳細コピー全文は、必要になった場合だけDiscordへ貼るか証拠ファイルとして渡す。

## 実施順（簡略版）

1. まず`区分=まずやる`の10本だけを順に実施する
2. 各行の`やること`を実施し、`OKの目安`だけを見る
3. `結果`へ`OK`／`気になる`／`実施できず`のいずれかを記入する
4. `気になる`の場合だけ、見えた事実を一言書く。原因推測やModの切り分けは不要
5. 可能なら公式Trade URLまたは画像名を`証拠URL・画像名`へ残す
6. 10本完了時点で一度Mac側へ返し、追加確認が本当に必要な範囲を絞る

### 記入例

- 正常に検索できた: `結果=OK`、ほかは空欄でよい
- 0件だったがエラーや不自然な表示はない: `結果=OK`、`気になったこと=0件`
- 0件で、条件が怪しく見える: `結果=気になる`、`気になったこと=火耐性だけONにすると0件`
- ヘッダーが違う: `結果=気になる`、`気になったこと=槍ではなくQuarterstaff表示`
- 品を用意できない: `結果=実施できず`、理由を一言書く

### 0件の扱い

検索0件だけでは不合格にしない。出品がない正常な0件と、検索条件が狭すぎる不具合を実機担当が
その場で区別する必要はない。0件になった場合、鰤さんは`0件`とだけ記録する。公式Trade URL、
画面画像、必要なら詳細コピーを材料に、Modを外した再検索・最終Trade2 JSON・出品有無の切り分けは
Mac側で行う。

### 実機で確認する範囲

実機では、Windows固有の表示・操作・クリップボード・通信・実API応答を確認する。Parser、identity、
Stat、最終Trade2 JSONの網羅性はP0自動監査が担保するため、64ケースすべてを人手で再検証しない。

構造監査は合成fixtureで分岐と最終Trade2 JSONを総当たりする。翻訳・identity・ゲーム内コピー固有の

Windowsでの見た目・操作感は`windows-test-run.csv`に残す。

再生成コマンド:

```bash
PYTHONPATH=. uv run --python 3.12 --with-requirements requirements.txt -- \
  python -m src.poetore.poe2.audit
```

## Windowsでの作業方法

作業票へ記録する`PoENaviコミット`と、起動した`poenavi-windows-<commit>`の末尾を一致させる。
`poenavi-windows-<commit>`は確認用スナップショットなので直接編集しない。Windows共有上に用意した
専用の作業コピーへ結果を記入し、確認後にMac正本へ取り込む。
