# ぽえとれ OBS配信モード 実装計画書

## 1. 目的

OBSの「ウィンドウキャプチャ」で、ぽえとれの検索結果を安定して配信・録画へ載せられるようにする。

通常利用では、現在どおり検索結果をPoE上のアイテム付近へ表示する。OBS配信モードを有効にした時だけ、OBSが選択するための専用ウィンドウを追加する。

## 2. 現状と原因

現在のぽえとれは、Windows上で次の2つの独立したトップレベルウィンドウを持つ。

- ぽえとれ本体：`PoetoreModeWindow`（`QMainWindow`）
- 検索結果：`PoetoreWindow`（`Qt.Tool`）

OBSのウィンドウキャプチャは、選択した1つのWindowsウィンドウ（HWND）を取得する。そのため、ぽえとれ本体をキャプチャしても、別HWNDである検索結果は合成されない。

検索結果は検索のたびに表示・終了し、AUTO-HIDEでも頻繁に閉じる。これをOBSが直接選ぶ方式では、ソースの再検出や非表示時の挙動が安定しにくい。

## 3. 要件

### 3.1 必須要件

- OBSのウィンドウ一覧に、識別しやすい固定タイトルで表示される
- 検索前から専用ウィンドウが存在し、検索を繰り返しても同じHWNDを維持する
- 通常の操作モード／AUTO-HIDEの挙動を変えない
- 検索結果が更新されるたび、OBS側の表示も追従する
- 検索中、成功、0件、エラー、poe.ninja価格の後着更新を反映する
- 検索結果を閉じても、OBS専用ウィンドウ自体は消えない
- OBS配信モードのON／OFFと専用ウィンドウの位置・サイズを保存する
- PoE1以外では有効にしない

### 3.2 品質要件

- 配信モードOFF時のCPU・メモリ負荷を増やさない
- 配信モードON時も、毎フレーム描画や高頻度ポーリングを行わない
- DPI 100%／Windows実利用倍率、マルチモニターで崩れない
- OBSを先に起動した場合、ぽえとれを先に起動した場合の両方で再選択しやすい
- 通常検索画面とOBS表示で、アイテム名・条件・価格が食い違わない

## 4. 採用方式

### 4.1 推奨：同一HWNDの折りたたみ式OBSウィンドウ

新しいトップレベルウィンドウ`PoetoreObsWindow`を追加する。

- 固定タイトル：`ぽえとれ - OBS配信用`
- OBS配信モードONの間は常設し、HWNDを作り直さない
- 待機中はドラッグ可能なタイトルバーだけを表示する
- 検索開始時に、同じウィンドウを下方向へ展開して検索結果を表示する
- 閉じる操作ではウィンドウを破棄せず、タイトルバーだけへ折りたたむ
- OBSはこの1つのウィンドウを継続してウィンドウキャプチャする

Overlay系ツールと同じく「普段は小さなバー、検索時だけ結果が下へ開く」使い方にする。ウィンドウの上端・左端を固定して下方向だけへ伸ばすことで、ユーザーが決めた配置を維持する。

### 4.2 検索処理と表示の分離

アイテム解析、検索条件生成、Trade API、Seller集約、poe.ninja、キャッシュは既存部品をそのまま1回だけ使用する。OBSモード専用の検索処理や二重API通信は作らない。

表示は画像ミラーではなく、既存の検索結果UIをOBSモード用の常設ウィンドウ内で使う。OBSモードでは検索結果ウィンドウの寿命と閉じ方だけを切り替える。

- 通常モード：従来どおり必要時に表示し、閉じる
- OBSモード：起動中は同じウィンドウを維持し、展開／折りたたみだけを行う

これにより通常画面とOBS画面の検索条件が分岐せず、画像化による文字のぼやけや拡大縮小も避けられる。

### 4.3 初期実装で採用しない方式

#### 検索結果をぽえとれ本体内へ統合

本体と同じHWNDになるが、アイテム付近へ表示する現在の操作性が失われる。通常利用への影響が大きいため採用しない。

#### 検索結果ウィンドウ自体をOBSで直接選ばせる

表示・終了を繰り返すため、OBSソースとしての安定性が低い。専用モードを作る目的を満たしにくい。

#### 同じ検索結果UIを二重生成

編集可能なWidgetと状態を2組持つことになり、条件・非同期検索・選択状態の同期が複雑になる。初期実装では避ける。

#### 検索結果を画像として別ウィンドウへミラー

通常画面とOBS画面を同時に出せるが、更新契機の管理、文字のぼやけ、リサイズ時の品質低下が発生する。折りたたみ式の単一ウィンドウで要件を満たせるため採用しない。

## 5. OBS専用ウィンドウの仕様

### 5.1 表示内容

展開時は、既存の検索結果UIをそのまま表示する。

- アイテム名とベース情報
- poe.ninja参考価格と7日推移
- 基本検索条件チップ
- Mod検索条件
- 検索状態
- 公式Tradeの出品一覧
- 警告・未対応条件の案内

OBS配信用ウィンドウ自体で、通常どおり条件編集と再検索ができる。

### 5.2 検索前の待機表示

まだ検索していない時は、高さ30～40px程度のタイトルバーだけを表示する。タイトルは`ぽえとれ - OBS配信用`とし、OBSでソースを設定する段階から識別できるようにする。

タイトルバーはドラッグ移動に対応し、移動先を保存する。検索結果はタイトルバーの直下へ展開する。

### 5.3 検索結果を閉じた時

右上の閉じるボタン、Esc、画面外クリックでは、ウィンドウを終了せずタイトルバーだけへ折りたたむ。次の検索で同じ位置から再び展開する。

AUTO-HIDEもOBSモードではウィンドウを破棄せず、従来の終了条件で折りたたむ。必要であれば、検索後の表示を配信上へ残しやすいよう「自動で折りたたまない」を追加設定にする。

### 5.4 背景

第1段階では不透明な通常テーマ背景を採用する。OBS側でクロップしてゲームキャプチャの上へ配置する。

透明背景はOBSのキャプチャ方式、Windowsの合成、Qtの半透明ウィンドウの組み合わせで差が出やすいため、第1段階の必須要件にしない。必要性が確認できた場合は、第2段階で次のいずれかを追加検討する。

- OBSのカラーキーで抜きやすい単色背景
- 透過対応の専用描画
- 背景色を設定画面から選択

### 5.5 サイズと位置

- 折りたたみ時はタイトルバーだけの固定高とする
- 展開時の初期サイズは、検索結果の小／中／大設定に合わせる
- タイトルバーをドラッグして移動できる
- 展開時は上端・左端を固定し、下方向へサイズを広げる
- 位置と展開時サイズは`config.json`へ保存する
- 「位置・サイズをリセット」を用意する
- 検索結果を閉じても、保存した展開時サイズは維持する

OBSではソースの外形がタイトルバー高と展開後の高さで変わるため、実機確認ではソースの左上固定と拡大率が維持されるかを重点確認する。必要ならOBS側のバウンディングボックス設定を案内する。

## 6. 設定UI

ぽえとれ設定画面の「検索結果・マップチェック画面」付近へ、`OBS配信`グループを追加する。

### 設定項目

- `OBS配信用ウィンドウを表示する`：ON／OFF
- `検索後に自動で折りたたまない`：初期値OFF
- `OBS配信用ウィンドウの位置・サイズをリセット`

第1段階では設定を増やしすぎず、背景色、余白、表示部位の選択は追加しない。

### 本体側の操作

ぽえとれ本体のヘッダーへ、配信状態を確認できる小さなボタンまたはメニュー項目を追加する。

- OFF時：`OBS`
- ON時：`OBS ON`
- クリック：専用ウィンドウを表示／前面化。折りたたみ中なら展開
- 右クリックまたは設定画面：配信モードのON／OFF

OBS用ウィンドウを通常の「常に最前面」対象にはしない。配信中にゲーム操作を邪魔しないよう、別モニターまたは画面外周へ置く前提とする。

## 7. 内部設計

### 7.1 追加候補

- `src/ui/poetore_obs_window.py`
  - `PoetoreObsWindow`
  - タイトルバーだけの折りたたみ状態
  - 既存検索結果UIを収める展開状態
  - 位置・展開時サイズ保存
- `tests/test_poetore_obs_window.py`
  - 新規モジュールに対応する専用テスト

### 7.2 既存コードの変更候補

- `src/poetore/ui.py`
  - 検索結果UIとトップレベルウィンドウの責務を必要最小限に分離
  - OBSモード時はcloseをcollapseへ切り替える
- `src/ui/poetore_mode_window.py`
  - OBS専用ウィンドウの生成・破棄・再表示
  - ぽえとれ終了時の後始末
- `src/ui/poetore_settings_dialog.py`
  - OBS配信設定の追加
- `default_config.json`
  - 初期設定値の追加

### 7.3 設定データ案

```json
{
  "poetore": {
    "obs_streaming": {
      "enabled": false,
      "keep_expanded": false,
      "geometry": {
        "x": null,
        "y": null,
        "width": null,
        "height": null
      }
    }
  }
}
```

未設定の既存ユーザーはOFFとして扱い、設定移行を不要にする。

### 7.4 状態遷移

```text
配信モードOFF
  └─ ON → OBS専用ウィンドウ生成 → タイトルバーだけ表示

折りたたみ表示
  └─ アイテム取得 → 同じHWNDを下へ展開
                     └─ 検索中表示
                         ├─ 成功 → 出品一覧を表示
                         ├─ 0件 → 0件案内を表示
                         └─ 失敗 → エラー案内を表示

検索結果表示
  ├─ 次の検索 → 新しい内容へ更新
  ├─ Esc／閉じる／画面外操作 → タイトルバーだけへ折りたたむ
  ├─ keep_expanded有効 → 検索結果を維持
  └─ 配信モードOFF → OBS専用ウィンドウを終了
```

## 8. 実装手順

### Phase 1：基盤

1. 設定スキーマと設定UIを追加
2. 固定タイトルの`PoetoreObsWindow`を追加
3. 折りたたみ／下方向への展開、位置・サイズ保存、リセットを実装
4. ON／OFFとアプリ終了処理を接続

### Phase 2：既存検索結果UIの常設ウィンドウ対応

1. 既存検索結果UIを通常／OBSの両ウィンドウ寿命で使えるよう整理
2. OBSモードのcloseをcollapseへ切り替える
3. 検索前、検索中、成功、0件、エラーで正しく展開・更新する
4. poe.ninjaの非同期更新を同じUIへ反映する
5. 表示サイズ変更と展開時リサイズへ追従する

### Phase 3：操作と仕上げ

1. 本体からOBS用ウィンドウを再表示・クリアできる導線を追加
2. 通常モード／AUTO-HIDEとの干渉を回帰確認
3. DPI・マルチモニター・長いMod一覧を調整
4. OBS設定手順をREADMEとnote記事へ追記

## 9. 自動テスト計画

### 設定

- 既存設定に`obs_streaming`がなくてもOFFで起動する
- ON／OFF、keep_expanded、geometryが保存・復元される
- 位置リセットでgeometryだけが消える

### ウィンドウ寿命

- ON時に専用ウィンドウが1つだけ生成される
- 複数回ON操作しても重複生成されない
- 通常検索結果を閉じても専用ウィンドウが残る
- OFFまたはアプリ終了で専用ウィンドウが確実に閉じる

### 同期

- 折りたたみ状態から同じHWNDのまま展開する
- 検索中、成功、0件、エラーが順番どおり反映される
- 古い検索の遅延レスポンスで新しい表示が上書きされない
- poe.ninjaの後着更新が現在のアイテムにだけ反映される
- Mod条件変更後の再検索内容が反映される

### 既存機能の回帰

- 操作モードのフォーカス、外側クリック、Esc終了
- AUTO-HIDEの非アクティブ表示、マウス移動、終了
- 検索結果位置のスタッシュ側／インベントリ側保存
- 小／中／大の表示サイズ
- Map ModチェックとCheat sheets

## 10. Windows＋OBS実機検証

自動テストだけでは、OBSが実際にどのHWNDを列挙・保持するかは証明できない。Windows実機で次を確認する。

### 基本確認

1. ぽえとれでOBS配信モードをONにする
2. OBSで「ウィンドウキャプチャ」を追加する
3. `ぽえとれ - OBS配信用`を選択する
4. キャプチャ方法をまず「自動」で確認する
5. 映らない場合だけ「Windows 10」と「BitBlt」を比較する
6. PoEのゲームキャプチャより上へ配置する

### 検証ケース

- OBS→ぽえとれの順で起動
- ぽえとれ→OBSの順で起動
- 通常検索を10回連続
- AUTO-HIDE検索を10回連続
- Esc／閉じる／AUTO-HIDE終了後にタイトルバーだけへ戻る
- keep_expanded有効時は検索結果が残る
- 0件、APIエラー、poe.ninja未掲載
- 小／中／大
- OBSシーン切り替え
- ぽえとれ最小化／トレイ格納
- OBS再起動後の再取得
- PoENavi自動アップデート後も設定が残る

### 証拠として残すもの

- OBSプレビューのスクリーンショット
- OBSで選択したウィンドウ名とキャプチャ方法
- 10回連続検索で欠落した回数
- OBSログ
- ぽえとれの性能ログ

## 11. 完了条件

次をすべて満たした時点で完了とする。

- 通常のぽえとれ操作を変えずに、OBS専用ウィンドウをON／OFFできる
- OBSのウィンドウキャプチャで専用ウィンドウを選択できる
- 通常検索／AUTO-HIDEの両方で検索結果が更新される
- 検索結果を閉じてもOBSソースが消えない
- 10回連続検索で表示欠落がない
- 検索中、成功、0件、エラー、poe.ninja後着更新が正しい
- 配信モードOFF時に既存挙動と性能へ影響がない
- 自動テスト、Windows実機、OBS実キャプチャの3段階で確認済み
- READMEとnote記事へOBS設定手順を記載済み

## 12. 将来拡張候補

初期版の実機評価後に、需要があれば次を検討する。

- 背景透過またはOBSカラーキー向け背景
- アイテム名・参考価格・出品一覧だけを表示する簡易レイアウト
- 配信者名やロゴを置ける余白
- 一定秒数後に待機表示へ戻す設定
- 検索結果の表示／非表示用ホットキー
- Map ModチェックのOBSミラー

これらは初期版へ混ぜず、まず「OBSから安定して同じウィンドウを取得できる」ことを優先する。
