# ぽえとれ 隠れ家滞在通知 仕様

更新日: 2026-09-28
状態: 実装済み・Mac自動検証完了・Windows実機確認待ち
対象: PoE 1／PoE 2のぽえとれモード

## 目的

集中してプレイしたい時だけ、隠れ家での滞在が指定時間に達したことを音声で知らせる。

常時監視にはせず、ぽえとれ上部の`集中`ボタンを押したセッションだけ`Client.txt`を監視する。通知はプレイを妨げる警告ダイアログではなく、柔らかい音声通知として扱う。

## 用語

- **集中モード**: 隠れ家滞在通知を一時的に有効にする実行状態。
- **隠れ家**: エリア名に日本語の`隠れ家`または英語の`Hideout`を含むエリア。英語判定は大文字・小文字を区別しない。
- **通知時間**: 隠れ家での連続滞在が通知対象になるまでの時間。
- **通知済み**: 繰り返しOFF時に、その滞在について音声通知を1回完了した状態。
- **エリア待ち**: 現在のPoEプロセス内で有効な最新エリアを確認できず、新しいエリアログを待っている状態。

UIと説明文では`警告`ではなく`通知`を使う。説明文では必要に応じて柔らかい`お知らせします`を使う。

## 初期値と保存

- 集中モードはぽえとれ起動時に毎回OFFとし、ON状態を保存しない。
- 通知時間の初期値は60秒。
- 通知時間は10秒以上60分以下、1秒単位で設定できる。
- 繰り返し通知の初期値はOFF。
- 通知音声の初期値は同梱のずんだもん音声。
- 音量の初期値は`50`。
- 通知時間、繰り返し、音声選択、音量は次回起動へ保存する。
- PoE 1とPoE 2で通知設定は共通とする。

想定する設定構造:

```json
{
  "poetore": {
    "hideout_notification": {
      "duration_seconds": 60,
      "repeat": false,
      "audio_source": "bundled",
      "custom_audio_display_name": "",
      "custom_audio_file": "",
      "volume": 50
    }
  }
}
```

カスタム音声の実体パスはアプリ管理領域から導出し、外部の元ファイルパスを設定値の正本にしない。`custom_audio_file`にはアプリ管理領域内のファイル名だけを保存する。

## 集中ボタン

ぽえとれ上部の既存アイコン列へ、文字付きの横長ボタンを常設する。クリックするたびにON／OFFを切り替える。

表示状態:

- OFF: `集中 OFF`
- ON・隠れ家外: `集中 ON`
- ON・現在地不明: `集中 ON（エリア待ち）`
- ON・隠れ家内: `集中 0:42`のように経過時間を表示
- 1回通知済み: `集中 1:23 ✓`のように経過時間と通知済みマークを表示

経過時間は通知後もリセットせず、隠れ家を出るまで増やし続ける。表示は残り時間ではなく経過時間とする。

通知時はボタンを約2秒だけ明るくする。赤色、警告マーク、モーダルダイアログ、Windowsトースト通知は使わない。

繰り返しON時は次回通知が残っているため、永続的な通知済みマークを表示しない。通知のたびに短時間の発光だけを行う。

## 集中モード開始

集中ボタンをONにする時だけ、選択中のPoE版について次を行う。

1. 対応する`Client.txt`を設定値から確認する。
2. 未設定または存在しない場合は既存の自動検出を試す。
3. 検出できない場合は集中モードをONにせず、`Client.txtを設定してください`と表示し、設定画面へ移動できるようにする。
4. 対応するPoEプロセスを一度だけ検索する。
5. PoEが起動していない場合は集中モードをONにせず、`PoEを起動してから集中モードをONにしてください`と表示する。
6. 対象プロセスのPID、プロセスハンドル、起動時刻を保持する。
7. 現在のPoEプロセス起動後に記録された最新の有効なエリアログを1回だけ確認する。
8. 現在地が隠れ家なら、集中ボタンをONにした瞬間を0秒としてカウントを開始する。過去の滞在時間は加算しない。
9. 現在地が隠れ家外なら、集中モードだけONにして次の隠れ家入場を待つ。
10. 有効な現在地を確定できない場合は`エリア待ち`にする。
11. `Client.txt`の末尾から新規追記の監視を開始する。

過去ログから現在地を復元する際も、タイマーの開始時刻は過去のログ時刻ではなく集中モードをONにした時刻とする。

## 現在プロセス内のエリア判定

古いセッションの最終エリアを現在地として誤認しないため、対象プロセスの起動時刻と`Client.txt`のログ日時を比較する。

- Windows APIの`GetProcessTimes`から対象プロセスの起動時刻を取得する。
- `Client.txt`からログ行の日時とエリア入場内容を取得する。
- プロセス起動時刻以降にある最新の有効なエリアだけを現在地候補にする。
- ログ日時を解析できない場合や、起動後のエリアログがない場合は推測せず`エリア待ち`にする。
- PoE 1／PoE 2双方の実ログ形式をテストへ固定してから有効化する。

時刻比較では、Windowsのプロセス時刻とログのローカル時刻を同じタイムゾーン・同じ精度へ正規化する。

## Client.txt監視

- ぽえとれ起動時には監視しない。
- 集中モードON中だけ、選択中のPoE版に対応する`Client.txt`を監視する。
- 集中モードOFFで監視を停止する。
- OFF中はログの追記確認、エリア解析、プロセス確認を行わない。
- ON開始時の現在地確認を除き、監視開始以前のログを新規イベントとして処理しない。
- 最小化中・タスクトレイ格納中も監視、カウント、音声通知を継続する。
- ぽえとれ終了時に監視を停止する。

新しいエリアログを受け取った時だけ、保持中のプロセスハンドルを非ブロッキングで確認する。定期的なプロセス一覧のポーリングや、終了待機専用スレッドは作らない。

保持中のプロセスが終了済みなら、前セッションのカウントと通知済み状態を破棄し、新しいPoEプロセスを取得してから新しいエリアを処理する。これにより、通知時刻より前にPoEを再起動し、最初に取得したエリアが隠れ家だった場合でも、旧セッションの滞在時間を引き継がない。

## 隠れ家判定とカウント

- エリア名に`隠れ家`または`Hideout`を含む場合は隠れ家と判定する。
- 自分の隠れ家と他人の隠れ家を区別しない。
- 隠れ家Aから隠れ家Bへ移動した場合、開始時刻、経過時間、通知済み状態、次回通知時刻を引き継ぐ。
- 隠れ家ではないエリアへ入った時だけ、経過時間、通知済み状態、次回通知時刻をリセットする。
- 隠れ家外ではタイマーを進めない。
- 時間計測はUI更新回数の加算ではなく単調増加時計の差分で求める。
- UIの経過時間表示は1秒単位で更新する。

## 通知タイミング

### 繰り返しOFF

- 連続滞在が通知時間へ達した時に1回だけ通知する。
- 通知後も経過時間表示を継続する。
- 同じ隠れ家滞在中は再通知しない。
- 隠れ家を出ると通知済み状態をリセットする。

### 繰り返しON

- 初回は通知時間へ達した時に通知する。
- 以後、同じ通知時間の間隔で繰り返す。
- 60秒設定なら、連続滞在の`1:00`、`2:00`、`3:00`で通知する。
- 隠れ家間を移動しても通知基準時刻をリセットしない。
- 再生中の音声と次の通知時刻が重なった場合、その回はスキップする。
- スキップした通知をキューへ積まず、後からまとめて再生しない。
- 次の通常の通知時刻に音声再生が終了していれば再生する。

## 通知直前のプロセス確認

音声を再生する直前に、集中モード開始時または直近の再取得時に保持したプロセスハンドルを非ブロッキングで確認する。

- 同じプロセスが生存中なら通知する。
- 終了済みなら音声を再生せず、カウントと通知済み状態をリセットする。
- 集中モード自体はONのまま`エリア待ち`へ移り、次の新規エリアログでプロセスを再取得する。
- PID番号だけで判定せず、保持したプロセスハンドルを使ってPID再利用による誤判定を防ぐ。

プロセス一覧を毎秒確認する処理は実装しない。

## PoE 1／PoE 2切替

集中モードON中にPoE版を切り替えた場合:

- 旧`Client.txt`の監視を停止する。
- 旧プロセスハンドルを閉じる。
- 経過時間と通知済み状態をリセットする。
- 切替先の`Client.txt`とPoEプロセスへ監視対象を切り替える。
- 切替先が隠れ家内でも、切替時点を0秒として開始する。
- 切替先の`Client.txt`を解決できない場合、または切替先のPoEプロセスが起動していない場合は、集中モードをOFFにして開始時と同じ案内を表示する。

## 設定画面

歯車内へ`隠れ家滞在通知`セクションを追加し、上から次の順に配置する。

1. 通知までの時間: `分`と`秒`
2. `通知を繰り返す`チェックボックス
3. 通知音声の表示名
4. `選択`ボタン
5. `標準に戻す`ボタン
6. 音量スライダー
7. `試聴`ボタン
8. 説明文: `集中モード中、隠れ家に設定時間滞在すると音声でお知らせします`

通知時間は合計秒へ正規化し、10秒未満または60分超を保存できないようにする。

### 集中モードON中の変更

- 通知時間変更: 現在のカウントと通知済み状態を0へ戻し、新しい時間で再開する。
- 繰り返し変更: カウントを維持し、次回通知から反映する。
- 音声または音量変更: カウントを維持し、即時反映する。
- 通知時間を現在の経過時間より短く変更しても、保存直後に突然通知せず、0秒から再開する。

## 通知音声

### 標準音声

ユーザー提供の次のファイルを標準音声としてアプリへ同梱する。

- SMB入力元: `/Volumes/Android共有用/集中モード.wav`
- 配布内の想定名: `assets/audio/hideout_focus_notification.wav`
- 読み上げ文: `そろそろ隠れ家を出る時間なのだ。いそげいそげー！`
- コンテナ: RIFF WAVE
- コーデック: PCM signed 16-bit little-endian
- サンプルレート: 48,000Hz
- チャンネル: モノラル
- 長さ: 3.954667秒
- サイズ: 379,752 bytes
- SHA-256: `07214ce09a4529be899f46ba2483e8d34c6ae22179c510f0c39b09f33d2a1e3e`

実装時は上記SHA-256と一致する入力だけを同梱し、ビルド設定と配布物の両方で収録を検証する。

### カスタム音声

- 対応形式はWAVとMP3。
- `選択`時にファイルが読み込めることを検証する。
- 選択した音声をPoENaviのユーザーデータ領域へコピーする。
- 元ファイルを移動・削除しても再生できるようにする。
- UIには元の表示名を保持する。
- `標準に戻す`で同梱音声へ切り替える。
- 標準音声とカスタム音声はPoE 1／PoE 2で共通とする。

### 音量

音量スライダーは整数`0`～`100`とする。

- `0`: 無音
- `50`: 音声ファイル本来の音量。初期値かつ`標準`位置
- `100`: 本来の約2倍の振幅、最大約+6dB
- 中間値の再生ゲインは`volume / 50`を基準とする。
- 50を超える増幅時は、オーバーフローや音割れを抑えるリミッターを通す。

音量0でも通知イベント自体は成立し、ボタン発光、通知済み状態、繰り返し間隔は通常どおり更新する。

`試聴`は現在選択中の音声と音量をそのまま使用する。

### 再生失敗

カスタム音声が欠損、破損、未対応、または再生開始に失敗した場合:

- その回は同梱の標準音声へフォールバックする。
- 非モーダル表示で`設定した音声を再生できなかったため、標準音声を使用しました`と知らせる。
- 保存済みのカスタム音声設定を勝手に標準へ書き換えない。
- 標準音声も再生できない場合はエラーを記録し、UIスレッドや集中モードを停止させない。

### 再生停止

- 集中ボタンをOFFにした場合、再生中の通知音声を即停止する。
- 隠れ家を出た場合、すでに開始した通知音声は最後まで再生する。
- ぽえとれ終了時は即停止する。
- 通知音声を多重再生しない。

## 集中モード停止

集中ボタンをOFFにした時:

- `Client.txt`監視を停止する。
- エリア状態、開始時刻、経過時間、通知済み状態、次回通知時刻を破棄する。
- 保持中のプロセスハンドルを閉じる。
- 再生中の通知音声を停止する。
- ボタン表示を`集中 OFF`へ戻す。

再度ONにした場合は、以前の状態を復元せず新しいセッションとして開始する。

## 性能要件

- 集中モードOFF中は、この機能による`Client.txt`監視、プロセス列挙、生存確認、タイマー更新を行わない。
- プロセス一覧の定期ポーリングを行わない。
- プロセス列挙は、集中モードON時と、既存ハンドルの終了をエリアイベントで確認した後の再取得時だけ行う。
- プロセス生存確認は新規エリアログ受信時と通知直前だけ行う。
- 音声の読込、変換、増幅処理でUIスレッドを長時間ブロックしない。
- 実装後、集中モードOFF／ON待機／隠れ家カウント中／音声再生中のCPU・メモリをWindows実機で比較する。

## エラー表示

- `Client.txt`未設定・未検出: 集中モードを開始せず、設定画面への導線を表示する。
- PoE未起動: 集中モードを開始せず、起動後の再操作を案内する。
- 起動後のエリア不明: 集中モードはON、`エリア待ち`表示とし、推測でカウントしない。
- カスタム音声再生失敗: 標準音声へフォールバックし、非モーダルで知らせる。
- ログ監視中の一時的な読込失敗: 集中モードをクラッシュさせず、次回追記で回復を試みる。重複通知はしない。

## 対象外

- 自分の隠れ家と他人の隠れ家の識別
- 隠れ家ごとの個別タイマー
- PoE 1／PoE 2別の通知音声・通知時間
- Windowsトースト通知
- モーダル警告ダイアログ
- 集中モードON状態の再起動復元
- 集中モード用グローバルホットキー
- プロセス一覧の定期監視

## 受け入れ条件

### 基本動作

- 起動時は必ず`集中 OFF`で、設定値だけが復元される。
- OFF中はぽえとれから`Client.txt`を監視しない。
- PoE 1／PoE 2の双方で、集中ON後の隠れ家入場からカウントできる。
- 隠れ家内でONにした場合、現在プロセス内のエリアと確認できた時だけON時点からカウントできる。
- 隠れ家Aから隠れ家Bへ移動してもカウントを維持する。
- 非隠れ家へ移動するとカウントと通知済み状態がリセットされる。
- 最小化・トレイ格納中も通知できる。

### 通知

- 既定60秒で1回だけ通知する。
- 繰り返しONでは同じ間隔で通知し、音声を多重再生しない。
- 通知後も経過時間表示が継続する。
- 1回通知後は`✓`が表示され、隠れ家退出で消える。
- 通知時にモーダル表示やWindowsトーストを出さず、ボタンだけが短時間発光する。

### ログ・プロセス

- 前回セッションの古い隠れ家ログを現在地として使わない。
- プロセス起動後の有効な最新エリアがない場合は`エリア待ち`になる。
- 通知直前に対象プロセスが終了済みなら音声を鳴らさない。
- 通知前にPoEを終了・再起動しても旧セッションの時間を引き継がない。
- 毎秒のプロセス列挙を行わないことをテストまたは計測で示せる。

### 設定・音声

- 通知時間を10秒～60分の1秒単位で保存・復元できる。
- WAV／MP3を選択し、元ファイル削除後もコピー済み音声を再生できる。
- `標準に戻す`と`試聴`が動作する。
- 音量`50`で原音相当、`100`で最大約+6dBとして再生できる。
- カスタム音声が再生できない時、設定を書き換えず標準音声へフォールバックできる。
- 同梱音声が仕様記載のSHA-256と一致する。

### 回帰・実機確認

- 既存のぽえとれ検索、AUTO-HIDE、タスクトレイ、PoE版切替、設定保存を壊さない。
- 集中モードOFF時に既存ぽえとれモードのサービス構成と常時負荷が増えていない。
- PoE 1／PoE 2の日本語・英語エリアログをテストする。
- 公式、Steam、Epicで使用される対象PoEプロセス名をWindows実機で確認する。
- WAVとMP3、標準音声、音量0／50／100、破損ファイルの再生経路をWindows実機で確認する。

## 実装前に確認する実物依存事項

次は仕様上の未決事項ではなく、実装・テスト時に実物で証明する項目とする。

- PoE 1／PoE 2の実`Client.txt`における日時書式とタイムゾーン
- 日本語`隠れ家`／英語`Hideout`の実ログ
- 公式、Steam、Epic各版の実行ファイル名と、選択中PoE版への正しい対応付け
- PyInstaller配布物でのWAV／MP3再生、停止、音量増幅、リミッター
- 標準音声ファイルのビルド収録とSHA-256一致
- Windows実機での集中モード各状態のCPU・メモリ比較
